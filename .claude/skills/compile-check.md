# 编译检查准则

## 核心规则

**任何代码修改动作执行后，必须确保不会产生编译错误。如果产生了编译错误，需要进行分析和解决。**

## 编译检查流程

### 1. 设置环境变量

```bash
source /home/sunee/Ascend/ascend-toolkit/set_env.sh
```

### 2. 执行编译

```bash
bash scripts/build.sh -DSOC=ascend950 reduce_sum
```

### 3. 结果处理

- **编译成功**：无报错则通过，继续后续工作。
- **编译失败**：
  1. 分析编译错误输出，定位错误原因和位置。
  2. 修复导致编译错误的代码。
  3. 重新执行编译检查，直到编译成功为止。
  4. 如果错误无法自行修复，向用户报告具体错误信息并请求协助。

## 注释修改规则

**已有注释一律不得修改或删除，除非删除整个函数/类/结构体。**

- **新增代码**：只能在新代码行上添加新注释，不得改动已有注释。
- **修改代码**：不得修改已有注释的内容、位置、格式。
- **删除代码**：
  - 部分删除（非整个函数/类/结构体）：保留被删代码行上的注释，追加到相邻保留代码行末尾。
  - 整体删除（整个函数/类/结构体全部删除）：允许连同函数体内注释一并删除。

**Why:** 已有注释可能包含历史设计意图或未完成的工作记录，部分删除时保留注释可以避免信息丢失。

## 适用范围

- 所有对 `.cpp`、`.h`、`.hpp`、`.c` 等 C/C++ 源文件的修改。
- 对 `CMakeLists.txt` 或其他构建配置文件的修改。
- 任何可能影响编译结果的代码变更。
